This step configures both hub and spoke routers on the conductor. You will first update the authority-level objects to support hub and spoke tenants, then configure each router's WAN interface, LAN interface, and service routes. The hub router provides direct internet breakout; the spoke router routes internet traffic to the hub over an SVR peer path.

All steps are performed from the **Conductor GUI** at `https://<conductor-public-ip>` unless otherwise noted.

:::note
If you prefer to apply configuration using the PCLI, the complete example configuration is available in the [Appendix](deploy_appendix_azure_hub_spoke.mdx).
:::

## Part 1: Update Authority-Level Configuration

The conductor must have the correct tenants and services configured before either router is activated. If you already completed the [Azure Conductor Deployment Guide](deploy_azure_conductor.mdx) and created a `corp` tenant and `Internet-Traffic` service, you can either rename those objects or create new ones as described below. This guide uses separate tenants for hub and spoke users.

:::note
Your conductor must already have an authority name and conductor address set. If these are not yet configured, complete steps 1–3 of [Configure the Conductor](deploy_azure_conductor_config.mdx) before continuing.
:::

### 1. Create the Hub Tenant 

The `hub-corp` tenant represents users on the hub router's LAN.

1. Under **Configuration** in the left panel, select **Authority**.
   
![Select Authority](/img/deploy-azure-select-authority.png)

2. Scroll to **Tenants** and select **ADD**.

![Add Tenant](/img/deploy-azure-select-tenant-add.png)

3. Enter the name `hub-corp` and select **SAVE**.

![Hub tenant](/img/deploy-azure-hs-hub-tenant.png)

4. Select **VALIDATE** then **COMMIT**.

### 2. Create the Spoke Tenant

The `spoke-corp` tenant represents users on the spoke router's LAN.

1. Return to **Tenants** (click the up arrow next to **Tenant**) and select **ADD**.
2. Enter the name `spoke-corp` and select **SAVE**.

![Spoke tenant](/img/deploy-azure-hs-spoke-tenant.png)

3. Select **VALIDATE** then **COMMIT**.

### 3. Create or Update the `Internet-Traffic` Service

The `Internet-Traffic` service matches all internet-bound traffic. Both tenants must be granted access so the hub can forward internet traffic for both hub LAN users and spoke LAN users arriving over SVR.

1. Under **Configuration** in the left panel, select **Authority**.

![Select Authority](/img/deploy-azure-select-authority.png)

3. Scroll to **Services** and select **ADD** (or select the existing `Internet-Traffic` service if it already exists).

![Add Service](/img/deploy-azure-hs-services.png)

4. Enter the name `Internet-Traffic` and select **SAVE**.

![Add Internet Traffic Service](/img/deploy-azure-service-int-traf.png)

5. Verify **Enabled** is set to `true`.

![Internet Traffic Service True](/img/deploy-azure-service-int-traf2.png)

6. Scroll to **Service Addresses** and select **ADD**. 

![Select Service Addresses](/img/deploy-azure-service-int-traf3.png)

7. Enter `0.0.0.0/0` and select **SAVE**.

![Address IP](/img/deploy-azure-service-address.png)

8. In the **Access Policy** field, add two entries:

   Scroll to **Access Policy** and select **ADD**.

      ![Add Access policy](/img/deploy-azure-hs-access-policies-select.png)

   - In the New Access Policy window, add **Source:** `hub-corp` and select **SAVE**.

      ![New Policy](/img/deploy-azure-hs-hubcorp-acc-policy.png)

   - Click the up arrow next to **Access Policy**.
   - Select **ADD**.
   - In the New Access Policy window, add **Source:** `spoke-corp` and select **SAVE**.

      ![New Policy](/img/deploy-azure-hs-spokecorp-acc-policy.png)

8. Select **VALIDATE** then **COMMIT**.

:::info
The `spoke-corp` access policy on the `Internet-Traffic` service allows traffic from spoke LAN users to be forwarded by the hub router when it arrives over the SVR peer path. Without this policy, the hub drops spoke-originated internet traffic.
:::

## Part 2: Configure the Hub Router

### Add the Hub Router to the Authority

1. In the Conductor GUI, click on Authority. 

   ![Conductor Authority](/img/dep-vmrouter-config-authority.png)

2. At the top of the list of Routers, select **ADD**. 

   ![Add Router](/img/dep-vmrouter-addrouter.png)

3. Enter the router `azure-hub-router` and click **Save**.

   ![New Router](/img/deploy-azure-newhub-rtr.png)

4. In the Basic Information screen, under **Inter-node Security Policy**, select `Internal`.

5. Below the **Basic Info** screen, click **ADD** next to **Nodes**. 

6. The **New Node** dialog is displayed - enter `node0`.

   ![New Node](/img/dep-vmrouter-newnode.png)

7. Click **Save**. The **Node** screen appears.

### Assign the Hub Router's Asset ID

The Asset ID allows the hub and conductor to fully connect, and allows the conductor to configure and control the hub router. 

On the Node screen: 
- Under **Associated Asset ID**, select the asset ID reported by the hub router VM.
- Set the Role to `Combo`. 

   ![Node Asset ID](/img/deploy-azure-node-basicinfo.png)

Select **VALIDATE** then **COMMIT**.

### 1. Configure the Hub WAN Interface

The WAN interface `ge-0-0` / `ssr-hub-wan`) connects to the internet, obtains a DHCP address, and carries both internet forwarding and conductor management traffic. The neighborhood topology is set to `hub`, which makes this router the internet gateway for spoke routers in the same neighborhood.

#### 1a. Create the Hub WAN Device Interface

1. In the Conductor GUI, navigate to the `azure-hub-router` router, then to node `node0`.
2. Scroll to **Device Interfaces** and select **ADD**.
3. Enter the name `wan-dev` and select **SAVE**.

   :::note
   To ensure successful onboarding, the `ge-0-0` interface MUST be configured as the WAN device interface. 
   :::

   ![Name the WAN Interface](/img/deploy-azure-wan-dev-intf.png)

4. In the Device Interface window, set the type to `ethernet`. When the **Identifier** field becomes visible, select VMBus UUID from the dropdown, and then enter the ID discovered in [Step 3](deploy_azure_hub_spoke_vmbus.mdx)

   ![Device Interface window](/img/deploy-azure-wan-dev-intf2.png)

#### 1b. Create the Hub WAN Network Interface

1. Under the WAN Device Interface, scroll to **Network Interfaces** and select **ADD**.
2. Enter the name `wan1` and select **SAVE**.

   ![New Network Interface](/img/deploy-azure-wan-dev-intf3.png)

3. On the Basic Information screen, set the following fields:

   - Global-ID: `1` 
   - Type: `external`
   - DHCP: `v4` - Azure assigns an IP via DHCP
   - Security Policy: **internal**

   ![WAN Basic Info](/img/deploy-azure-wan-dev-intf4.png)

4. Scroll to Management Traffic Settings and set:

   - Conductor: `true`  - Marks the interface for conductor connectivity
   - Management Enabled: `true` - Enables management over forwarding
   - Management Vector Name: `mgmt-vec-wan`
   - Management Vector Priority: `100`
   - Default Route: `true` - Linux uses this interface as its default route

   ![Management Vector](/img/deploy-azure-wan-dev-intf5.png)

5. Scroll down to Network Interface settings, and set **Source NAT** to `true`. This is required for management over forwarding.

   ![Set Source NAT](/img/deploy-azure-wan-dev-intf6.png)

6. Scroll to **Neighborhoods** and select **ADD**.
   - Enter neighborhood name `internet`.

   ![New Neighborhood](/img/deploy-azure-wan-dev-intf7.png)

   - Select **SAVE**.
   - Verify **Topology** is set to `hub`.

   ![Topology](/img/deploy-azure-wan-dev-intf8.png)

:::important
Setting **Topology** to `hub` on the hub router's neighborhood is what distinguishes it from a spoke. The conductor uses this topology to auto-generate adjacencies between the hub and any spoke routers that share the same neighborhood name with topology `spoke`.

`Conductor`, `Source NAT`, and `Default Route` must all be `true` on the WAN management interface. Management traffic originates from the `169.254.x.x` range and must be source-NAT'd to a routable address before leaving the interface.
:::

### 2. Configure the Hub LAN Interface

The LAN interface (`ge-0-1` / `ssr-hub-lan`) connects to the hub private subnet and assigns the `hub-corp` tenant to inbound traffic.

#### 2a. Create the Hub LAN Device Interface

1. In the Conductor GUI, navigate to the `azure-hub-router` router, then to node `node0`.
2. Scroll down to **Device Interfaces** and select **ADD**.
3. Enter the name `lan-dev` and select **SAVE**. This adds a physical device name for you to assign your LAN interface.

   ![New LAN](/img/deploy-azure-lan-dev-intf1.png)

5. In the Device Interface Type Settings window, set the type to `ethernet`. When the **Identifier** field becomes visible, select VMBus UUID from the dropdown, and then enter the ID discovered in [Step 3](deploy_azure_hub_spoke_vmbus.mdx). Set Forwarding to `true`.

![Device Interface Type](/img/deploy-azure-lan-dev-intf2.png)

#### 2b. Create the Hub LAN Network Interface

1. Under the LAN Device Interface, scroll down to **Network Interfaces** and select **ADD**.

   ![Add LAN1](/img/deploy-azure-lan-dev-intf3.png)

2. Enter the name `lan1` and select **SAVE**.

   ![New Dev Interface](/img/deploy-azure-lan-dev-intf4.png)

3. On the Basic Information screen, set the following fields:

   - Type: `external` 
   - Global-ID: `2` 
   - DHCP: `disabled` 
   - Tenant: `hub-corp` - Assigns all inbound LAN traffic to the hub-corp tenant
   - Security Policy: `internal`

   ![Network Interface](/img/deploy-azure-lan-dev-intf5.png)

4. Scroll down to Network Interface settings, and set **Source NAT** to `true`. 

5. Scroll to **Interface Addresses** and select **ADD**.

![Add Intf Address](/img/deploy-azure-lan-dev-intf6.png)

6. Enter the following IP address and prefix.

   - IP Address: `10.0.2.1`
   - Prefix Length: `24`

![New Intf](/img/deploy-azure-lan-dev-intf7.png)

### 3. Configure Hub DNS

Configure DNS so the hub router can resolve FQDNs for conductor connectivity and software downloads.

1. Return to the **Router** level for `azure-hub-router`. You can either click the up arrow at the top of the screen until you reach the `azure-hub-router` level, or select the down arrow to the right of the Network Interface heading and select the `azure-hub-router`.

![Navigation](/img/deploy-azure-lan-dev-intf8.png)

2. Scroll to **DNS Config** and select **ADD**.

![Interface and DNS addresses](/img/dep-vmrouter-wandev11.png)

3. In the New DNS Config window, use the Mode dropdown to set the mode to **Static**, and click **SAVE**.

![DNS Mode](/img/deploy-azure-lan-dev-intf9.png)

4. In the DNS Server Address section, click ADD.
5. Enter 1.1.1.1 and click SAVE.

![DNS Server Addresss](/img/deploy-azure-lan-dev-intf10.png)

6. Click **ADD** again.
7. Enter 8.8.8.8 and click SAVE.

![DNS Server Addresss List](/img/deploy-azure-lan-dev-intf11.png)

### 4. Create the Hub Internet Service Route

The hub routes internet-bound traffic (from both its own LAN users and spoke users arriving over SVR) directly out through its WAN interface.

1. Return to the **Router** level for `azure-hub-router`.
2. Scroll down to **Service Routes** and select **ADD**.
3. Enter the name `internet-breakout` and select **SAVE**.

![Service Route Name](/img/deploy-azure-lan-dev-intf12.png)

4. Under Service Route Information, set the **Service Name** to `Internet-Traffic` 

![Service Route Info](/img/deploy-azure-lan-dev-intf13.png)

5. Under Service Route Type, select **Service Agent** from the **Type** dropdown.

![Service Route Details](/img/deploy-azure-lan-dev-intf14.png)

5. Scroll to **Next Hops** and select **ADD**.
   - Node Name: `node0`
   - Interface: `wan1`
6. Select **SAVE**.

![New Next Hop](/img/deploy-azure-lan-dev-intf15.png)

7. Select **VALIDATE** then **COMMIT**.

### 4. Create the Spoke Internet Service Route

The spoke router does not break out internet traffic directly. Instead, it forwards internet-bound traffic to the hub router over the SVR peer path established by the shared `internet` neighborhood.

1. Return to the **Router** level for `azure-spoke-router`.
2. Scroll to **Service Routes** and select **ADD**.
3. Enter the name `internet-via-hub` and select **SAVE**.

![Service Route Name](/img/deploy-azure-spoke-lan-dev-intf12.png)

4. Under Service Route Information, set the **Service Name** to `Internet-Traffic` 

![Service Route Info](/img/deploy-azure-spoke-lan-dev-intf13.png)

5. Under Service Route Type, select **Peer Service Route** from the **Type** dropdown. This routes internet traffic to a peer router via SVR.

6. Under **Peer**, add `azure-hub-router`. The hub router provides internet breakout for the spoke.

![Service Route Details](/img/deploy-azure-spoke-lan-dev-intf14.png)

7. Select **VALIDATE** then **COMMIT**.

:::info
The `peer service route` type directs matched traffic over the SVR path to the named peer router. The hub's `internet-breakout` service route then forwards that traffic to the internet. This is the SSR hub-and-spoke internet breakout pattern.
:::

## Verify Connectivity

After committing all configuration, all nodes must reach the `synchronized` state. From the Conductor GUI, select **Routers** to view their status. Once reached, verify both routers are online and forwarding traffic correctly.

### Verify Both Routers Are Connected to the Conductor

From the Conductor GUI, select **Routers**. Select the individual routers to see their status. 

Both `azure-hub-router` and `azure-spoke-router` should show a **Connected** status within 2–5 minutes of the commit.

Both routers should appear with status `Up`. After SVR adjacencies form, a third entry for the hub-to-spoke peer should also appear. To view this, click on a router and scroll down to the Peer Paths section.

### Verify SVR Peering Between Hub and Spoke

From the hub router, the spoke router should appear as an SVR peer with status `Up`.

From the spoke router, the hub router should appear with status `Up`.

### Verify ARP on the WAN Interfaces

Azure gateways do not respond to ICMP ping. Use the ARP table to verify WAN connectivity on each router:

```
admin@node0.azure-hub-router# show arp
admin@node0.azure-spoke-router# show arp
```

Look for **valid** ARP entries on the `wan1` interface of each router.

### Verify Internet Reachability

From the hub router:

```
admin@node0.azure-hub-router# ping 8.8.8.8
```

From the spoke router:

```
admin@node0.azure-spoke-router# ping 8.8.8.8
```

Both routers should reach the internet. Spoke internet traffic traverses the SVR peer path to the hub before being forwarded to the internet.

### Verify Service Paths

From the spoke router, confirm that internet traffic resolves through the hub:

```
admin@node0.azure-spoke-router# show service-path
```

The `Internet-Traffic` service should show a path type of `peer` with `azure-hub-router` as the next-hop peer.

## Configuration Summary

### Hub Router

| Object | Name | Key Settings |
|--------|------|-------------|
| Router | `azure-hub-router` | combo node |
| WAN Device Interface | `wan-dev` | VMBus UUID, forwarding `true` |
| WAN Network Interface | `wan1` | DHCP v4, conductor, management, source-nat, default-route, neighborhood `internet` topology `hub` |
| LAN Device Interface | `lan-dev` | VMBus UUID, forwarding `true` |
| LAN Network Interface | `lan1` | Tenant `hub-corp`, static `10.0.2.1/24`, source-nat |
| DNS | manual | `1.1.1.1`, `8.8.8.8` |
| Service Route | `internet-breakout` | `Internet-Traffic` → `node0/wan1` (direct breakout) |

### Spoke Router

| Object | Name | Key Settings |
|--------|------|-------------|
| Router | `azure-spoke-router` | combo node |
| WAN Device Interface | `wan-dev` | VMBus UUID, forwarding `true` |
| WAN Network Interface | `wan1` | DHCP v4, conductor, management, source-nat, default-route, neighborhood `internet` topology `spoke` |
| LAN Device Interface | `lan-dev` | VMBus UUID, forwarding `true` |
| LAN Network Interface | `lan1` | Tenant `spoke-corp`, static `10.0.4.1/24`, source-nat |
| DNS | manual | `1.1.1.1`, `8.8.8.8` |
| Service Route | `internet-via-hub` | `Internet-Traffic` → peer `azure-hub-router` (via SVR) |
