Operating the SSR as a dual-node HA pair with different versions of software on each node outside of an upgrade maintenance window is not supported; doing so may result in the failure of HA state updates to flow from the Active node to the Standby node.

<!-- truncate -->

**Issue ID:** I95-66861

**Last Updated:** 2026-10-28

**Introduced in SSR Version:** N/A

**Resolved in SSR Version:** N/A

### Problem

When upgrading the SSR dual-node HA router, each node is upgraded in succession, and at the midpoint of the upgrade, each node is running a different version of SSR software.  The supported upgrade procedure ensures that the Active node is always running the earlier software version during this temporary transitional stage to allow HA state updates to flow during this temporary period of mixed software versions.  Users that deviate from this approach and operate with the later software version on the Active node during this temporary transitional stage will encounter failure to maintain HA state updates to the Standby node.

As an example scenario, the SSR Routing Manager process runs only on the Active node. This process distributes route information to the routing agents on both HA peers. When the Active node is running SSR-7.0.0 or later software and the Standby node is running SSR-6.3 or earlier software, the routing agents on the Standby node cannot process routing updates from the Routing Manager process.  As a result, the Standby node routing table becames stale, and as a result the forwarding table is effectively corrupted.

### Cause

Software modules on the Standby node are not guaranteed to be able to consume HA state updates from their peer modules on the Active node when the Active node is running a later version of software than the Standby node.  Following the upgrade procedure for Mist-based and Conductor-based deployments ensure that this issue is not seen.  Deviating from the supported procedure exposes HA state update failures.

### Resolution

As a best practice, the network operator should minimize the duration of the temporary transitional stage when the two HA peers are running different versions of SSR software.

During the temporary transitional stage, the Active node must always be running an earlier software version than the Standby node.

Users should never intervene or interrupt the upgrade for the purpose of running with the later version of software on the Active node while keeping the earlier version of software running on the Standby node.
