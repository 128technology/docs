Intermittent SNAT Traffic Issues After HA Upgrade to SSR 7.0.x

November 23, 2026

Following software upgrade of an SSR High-Availability (HA) router, traffic using Source NAT (SNAT) or Waypoint resources may fail intermittently on the first upgraded node.

Issue ID: I95-66933

Last Updated: 2026-11-23

Affected SSR Versions: 7.0.5, 7.0.6, 7.0.7

Fix Planned for SSR Version: 7.0.8

Symptom​

The issue is exposed following an upgrade on an HA router between the versions listed below. After the second HA node completes its upgrade, traffic flowing through the first upgraded node may fail intermittently as a result of SNAT and/or Waypoint resource allocation failures. Logs may show indication of resource allocation errors, as shown below:

WayPointException: Failed to allocate WayPoint ports (possibly exhausted)

This issue is exposed during HA router upgrade between the following SSR releases:

Upgrade From VersionsUpgrade To Versions
7.0 release: 7.0.3 or earlier
6.3 release: 6.3.6 or earlier
6.2 release: 6.2.9 or earlier		7.0.5, 7.0.6, and 7.0.7

This issue is not exposed in SSR release 7.1 and later when you use the default leadership election mode.

Cause​

SNAT and Waypoint resources are maintained in a Redis database which is synchronized between HA nodes. During an upgrade between the affected versions, the first upgraded node's Redis database is unable to synchronize with the pre-upgrade master.

The problem is hidden until the second node (original Redis master) goes down for its upgrade. The first-upgraded node then becomes master with an unsynchronized Redis database. The second-upgraded node initializes its own NAT-port and waypoint records, but the database is missing the records that should have been initialized by the first upgraded node. This can cause intermittent traffic issues associated with that node.

Note that the issue may be masked if the second node goes down for upgrade before the first node’s one-hour recovery timer expires.

Workaround​

After upgrading both nodes, restart the first upgraded node to re-establish Redis replication as follows:

  1. Upgrade the first node.
  2. Upgrade the second node.
  3. Restart the first node.

After restarting the first upgraded node, confirm that both nodes complete post-upgrade health check and upgrade MOP validation steps. Additionally, To verify that the first node correctly re-establishes Redis synchronization, execute the following and confirm that the output aligns with the "healthy" example shown in the table.

redis-cli info replication | egrep 'master_port|master_link_status'
FieldHealthyUnhealthy
master_port637957005
master_link_statusupdown

Contact HPE support if any of the following are observed following the upgrade of an HA router between the affected routers:

  • the verification step above produces output that aligns with the "unhealthy" example.
  • traffic is failing on the first upgraded node
  • logs indicate resource allocation errors involving SNAT and/or Waypoint resources

Resolution​

A fix is planned for SSR 7.0.8. Until the fix is available, use the workaround when upgrading an HA pair across the affected versions.
